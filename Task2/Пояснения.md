## Пояснения к архитектуре MVP с учетом Data Privacy

### Ключевые компоненты для обеспечения конфиденциальности данных:

1. **API Gateway**:
    - Единая точка входа для всех API
    - Централизованная аутентификация и авторизация
    - Фильтрация и валидация запросов
    - Предотвращение атак (CSRF, XSS, инъекции)

2. **Сервис аутентификации**:
    - Реализация OAuth2/OIDC для безопасной аутентификации
    - Многофакторная аутентификация для доступа к чувствительным данным
    - Управление ролями и правами доступа (RBAC)
    - Атрибутивный контроль доступа (ABAC) для особых случаев

3. **Сервис классификации данных**:
    - Автоматическое тегирование данных по категориям чувствительности
    - Определение правил обработки для каждой категории
    - Метаданные о сроках хранения и условиях удаления

4. **Сервис аудита**:
    - Журналирование всех операций с конфиденциальными данными
    - Обнаружение аномального поведения пользователей
    - Оповещения о подозрительной активности
    - Неизменяемые журналы для расследования инцидентов

5. **Защищенные базы данных**:
    - Шифрование данных в состоянии покоя (TDE)
    - Разделение данных по доменам и уровням чувствительности
    - Псевдонимизация идентификаторов
    - Строгий контроль доступа на уровне СУБД

### Механизмы защиты данных:

#### При хранении:
- Шифрование на уровне базы данных (TDE)
- Шифрование отдельных полей с чувствительными данными
- Псевдонимизация идентификаторов пациентов
- Маскирование данных при отображении (например, частичное скрытие номеров телефонов)
- Разделение данных по категориям в разных схемах/таблицах

#### При передаче:
- TLS 1.3 для всех соединений
- JWT с коротким сроком жизни для аутентификации
- Подписание и шифрование токенов
- Взаимная аутентификация (mTLS) для интеграций с внешними системами
- Минимизация передаваемых данных (принцип минимальных привилегий)

#### При обработке:
- Валидация входных данных
- Принцип наименьших привилегий для сервисов
- Обезличивание данных для аналитики
- Аудит всех операций с чувствительными данными

### Периоды и условия уничтожения конфиденциальных данных:

1. **Медицинские данные**:
    - Срок хранения: 25 лет с момента последнего визита (в соответствии с законодательством)
    - Автоматическое архивирование после 5 лет неактивности
    - Автоматическое уничтожение по истечении срока хранения

2. **Контактные данные**:
    - Срок хранения: 5 лет с момента последнего визита
    - Автоматическое уничтожение по истечении срока
    - Немедленное удаление по запросу пациента (право на забвение)

3. **Финансовые данные**:
    - Срок хранения: 5 лет (законодательное требование)
    - Автоматическое уничтожение по истечении срока
    - Обезличивание для долгосрочного хранения в аналитических целях

4. **Данные аудита**:
    - Срок хранения: 3 года
    - Архивирование с шифрованием после 1 года
    - Автоматическое уничтожение по истечении срока

### Интеграция с лабораторией анализов:

- Взаимная аутентификация (mTLS) для безопасного соединения
- Минимизация передаваемых данных (только необходимые идентификаторы)
- Обезличивание данных при передаче (использование временных идентификаторов)
- Шифрование всего трафика
- Детальный аудит всех операций обмена данными
- Контракты API, скрывающие конфиденциальные данные
